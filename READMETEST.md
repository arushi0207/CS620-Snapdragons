# 📖 Project Overview

**SpeakEasy** is an AI-powered public-speaking coach that analyzes a user’s presentation video and returns:

- **Structured visual-only feedback** generated by **Qwen2-VL-2B-Instruct**
- A **data-driven speaking score (0–100)** computed using a custom **ContextRetriever** similarity model
- **Neighbor examples** retrieved from a labeled coaching dataset
- A fully integrated **React frontend** that shows upload progress, a custom *Analyzing…* overlay, and final results

The end-to-end system performs three major steps:

---

## 1️⃣ Lightweight Video Preprocessing
- Each uploaded video is stored under a unique `runs/<job_id>/` directory  
- Video is **downscaled to 360p using FFmpeg** for faster inference  
- ~5 frames are sampled per video for efficient **CPU-only** execution  
- These frames are passed to the language-vision model

---

## 2️⃣ Vision-Language Model Evaluation (Qwen2-VL on CPU)

We run:

```bash
Qwen/Qwen2-VL-2B-Instruct (PyTorch CPU)
```

to produce:

1. **Overall Summary**  
2. **Strengths**  
3. **Opportunities for Improvement**  
4. **Actionable Suggestions**

This evaluation is **visual-only** — the model does *not* analyze audio or speech content.

The backend invokes this through:

```bash
python -m scripts.llm_eval --model qwen2-pt --num-frames 5
```

### 3️⃣ ContextRetriever Scoring System

Instead of using a placeholder score, **SpeakEasy computes a real numerical score** using an embedding-similarity approach.

#### **How it works**
1. The LLM-generated summary is embedded using:  
   **`Alibaba-NLP/gte-Qwen2-1.5B-instruct`**
2. The embedding is compared against a dataset of **labeled public-speaking examples**
3. The **top-k most similar examples** are selected
4. Their scores are aggregated to produce:
   - **Overall score (0–100)**
   - **Neighbor examples** shown to the user

This enables outputs like:

> **“Your speaking score is 82%.”**  
> instead of a static or dummy score.

---

### 4️⃣ Frontend Integration (React)

The React frontend delivers a polished user experience, including:

- **Drag-and-drop video upload**
- **Real-time percentage progress** during upload
- A fullscreen **“Analyzing…” overlay** while backend inference runs
- A detailed results page featuring:
  - Rounded score (e.g., **82%**)
  - Summary, strengths, and opportunities
  - Neighbor examples retrieved via the ContextRetriever
- **Dark mode support**
- Responsive UI layout for desktop and mobile

The frontend sends requests to the backend via:

```bash
POST /api/analyze
```
which triggers the full evaluation pipeline in the FastAPI backend.

## ▶ Running the Project

### Start the backend server
```bash
uvicorn backend.server:app --reload
```

This exposes the main API endpoint:

```bash
POST /api/analyze
```

### What the Backend Does
- Saves the uploaded video  
- Downscales it to **360p** using FFmpeg  
- Samples frames  
- Runs **Qwen2-VL** for visual-only evaluation  
- Runs **ContextRetriever** to compute:
  - Overall score (0–100)
  - Neighbor examples  
- Returns a structured JSON response  

### What the Frontend Displays
- Rounded score  
- Summary  
- Strengths & opportunities  
- Neighbor examples  

## ▶ Running Qwen2-VL Manually

```bash
python -m scripts.llm_eval \
  --video input.mp4 \
  --out runs/test \
  --model qwen2-pt \
  --num-frames 5 \
  --max-new-tokens 512
```

python -m scripts.extract_from_video \

## What Works?
- End-to-end pipeline successfully processes a video and extracts visual features.
- Annotated video can be generated showing tracking overlays.
- LLaVA-OneVision and Qwen3-VL generate textual feedback about presentation quality.
- Placeholder scoring system outputs a basic score.
- ONNX export for Qwen3-VL works for Snapdragon-aligned deployment.


## What does not work and the current limitations?
- The scoring system is not a trained model — it is a placeholder (not based on real human-rated data).
- No integrated front-end user interface yet — results are JSON/terminal output.
- Vision-language ONNX inference pipeline is not implemented yet (PyTorch only).
- Limited testing of features across diverse speakers, lighting environments, and video formats.
- High GPU requirement for VLM evaluation; CPU inference is slow.

## What we would work on next?
- Replace placeholder scoring with a real ML-trained scoring model.
- Build a simple UI that allows users to upload a video and view feedback in one place.
- Add an ONNX-based runtime path for full Snapdragon deployment.
- Conduct broader testing to improve robustness across different speaking styles.
- Merge score + text feedback into a single structured coaching report.
